## 2. 演算法訊號解讀

### 三個關鍵演算法訊號（2026 Q2 持續有效）

**訊號一：輪播完整閱讀率（P7 誘因設計）**
演算法把「滑完整份輪播」視為高品質互動信號，權重等同留言。本週五篇全部維持 P7 = Tag/收藏誘因句設計：
- Day 53（workplace）P7：「Tag 那個接過『可以改回去嗎』需求的工程師，你們不孤單」
- Day 54（home_meme）P7：「Tag 那個組 IKEA 前先看說明書版本號的工程師」
- Day 57（tech）P7 收藏金句：「API 讓你不需要知道背後怎麼實作，但你得尊重它的 rate limit」

**訊號二：DM 轉傳率（演算法最高權重互動）**
- Day 53（需求改回去）：工程師傳給PM或同事，「就是這樣！」確認型轉傳
- Day 55（三小時會議結論再開一次）：上班族傳給同事，破圈最強一篇
- Day 56（假日行程不能臨時改）：另一半傳給工程師對象「你就是這樣」指認型轉傳

**訊號三：留言深度（來回對話 > 單句）**
- Day 53 發文後置頂：「你收過最荒謬的需求改回去經歷是什麼？留言分享」
- Day 56 發文後置頂：「工程師假日行程被臨時改你怎麼反應？A. 默默重算 B. 說不行 C. 外包給另一半決定」
- Day 57 發文後置頂：「你認為最準確的 API 生活比喻是什麼？留言比喻」

### 三個即刻執行的優化動作

1. **Day 53 發文時段**：週一或週二 12:00–13:30（工程師午休憤怒共鳴高峰，需求改回去這個痛點在周初最新鮮）

2. **Day 55 限時動態策略**：開會結論篇發文後分享到限時動態，加「你的公司開完會最後決定再開一次嗎？」投票（每週至少一次 / 不，我們直接散會），低成本引流回貼文留言

3. **Day 57 留言區技術補充**：API 篇發文後在留言補一條「延伸：rate limit 就是——不管你叫媽咪幾次，她只在心情好的時候回應 😂」引導非工程師也能留言參與

## 4. 下週策略方向

### 核心目標：換氣拓圈 ＋ 為 Day 57 tech 爆款鋪路

Day 52 的版本控制 tech 篇已積累高收藏信號，演算法正在學習「這個帳號的知識型輪播值得推給更大受眾」。本週策略分三層：

**第一層：workplace 引爆（Day 53）**
需求改回去是工程師圈最高共鳴的血淚情境。週一/二午休發文，讓工程師主動 Tag PM 或同事，在帳號觸及還熱的時候把互動信號拉高，告訴演算法這個帳號有社群黏性。

**第二層：home_meme 雙打（Day 54、56）**
IKEA 篇（週中）和假日行程篇（週五）分別從「生活幽默」和「伴侶情境」兩個角度擴大非工程師觸及。IKEA 是全台灣人共同語言，假日行程是情侶/夫妻日常，兩篇合力打通「工程師圈外」的受眾池。

**第三層：tech 收官（Day 57）**
在觸及面積已被本週前四篇撐大後，API 篇作為週末慢讀型貼文收割收藏。餐廳服務生比喻是目前所有 API 解釋中最通俗的一個，「把拔是媽咪的API嗎」這個 Anna 反殺將推動截圖和分享。

### 中期方向（Day 58–63 預告）
完成 Day 57 API 後，進入第三季「互動深化期」：
- 增加限時動態問答引流（每週 1–2 則）
- 考慮加入 tech 系列「工程師術語家族圖鑑」連續篇（Cache、Bug、Deploy、PR Review）
- workplace 引入「客戶需求語錄」系列（把真實模糊需求翻譯成技術規格）
